# ระบบติดตามงานตัดกล่องตัวอย่าง

หน้าเว็บสำหรับบันทึกและติดตามสถานะงานตัดกล่องตัวอย่าง มีระบบ Login แยกสิทธิ์ตามหน้าที่
และส่งอีเมลแจ้งเตือนอัตโนมัติ ข้อมูลทั้งหมดเก็บใน Google Sheet ฟรี ไม่มีค่าใช้จ่าย

ฟิลด์ในระบบอ้างอิงตามฟอร์มกระดาษ **ใบบันทึกงานตัดกล่องตัวอย่าง** ที่ใช้อยู่จริง

## บทบาทผู้ใช้

| บทบาท | ทำอะไรได้ | ทำไม่ได้ |
|---|---|---|
| **ช่างตัด** (`cutter`) | บันทึกงานที่ตัดเสร็จแล้ว · **ดึงข้อมูลจากระบบ Presales ด้วย request_id** หรือกรอกเอง · ลูกค้า / รหัสสินค้า / RSC-Tele / DieCut / Accessory / ลอน / จำนวน / **AE** / กำหนดส่ง / **สถานที่จัดส่ง** / หมายเหตุ · **กด "ส่งมอบแล้ว" เมื่อนำของไปวางที่จุดส่งมอบ** · ยกเลิกงาน · เปิดงานที่ยกเลิกกลับมา · **เข้าหน้าตั้งค่า** — แก้อีเมลแจ้งเตือนและ CC · จัดการรายชื่อ AE · ตรวจโควตาเมล · ล้างประวัติทั้งหมด | กรอกผู้ติดต่อ เบอร์โทร ทะเบียนรถ · กด "ส่งแล้ว" |
| **จัดส่ง** (`shipping`) | กรอก **ผู้ติดต่อ / เบอร์โทร / ทะเบียนรถ** · แก้สถานที่จัดส่ง · กด "ส่งแล้ว" | บันทึกงานใหม่ · แก้ข้อมูลลูกค้า/จำนวน/AE |
| **AE / Artwork** (`viewer`) | เปิดดูสถานะทุกงาน และดูสรุปประจำวัน | แก้ไขทุกอย่าง |

## การไหลของงาน

```
ช่างตัด กด "บันทึกงาน"      →  รอส่งมอบ     ยังไม่มีเมลออก
ช่างตัด กด "ส่งมอบแล้ว"     →  รอส่ง        📧 แจ้งฝ่ายจัดส่ง
ฝ่ายจัดส่ง กรอกทะเบียนรถ
           กด "ส่งแล้ว"      →  ส่งแล้ว       📧 แจ้ง AE ของงานนั้น
```

สถานะมี 4 แบบ: **รอส่งมอบ → รอส่ง → ส่งแล้ว** และ **ยกเลิก**

> **ทำไมต้องแยกเป็นสองจังหวะ** — ตอนบันทึกงาน ของยังอยู่ที่โต๊ะช่างตัด ยังไม่ได้เอาไปวางที่จุดส่งมอบ
> ถ้าเมลออกตั้งแต่ตอนนั้น ฝ่ายจัดส่งจะเดินไปรับแล้วไม่เจอของ
> **เมลจึงออกตอนช่างตัดกด "ส่งมอบแล้ว" เท่านั้น** ซึ่งแปลว่าของพร้อมให้ไปรับจริง

> **ปุ่ม "ส่งมอบแล้ว" เป็นของช่างตัดเท่านั้น** — คนที่เอาของไปวางคือคนกด
> ระบบกันการกดซ้ำไว้ที่เซิร์ฟเวอร์ เมลจึงออกฉบับเดียวต่อการส่งมอบหนึ่งครั้ง

> เผลอกดส่งมอบทั้งที่ยังไม่ได้เอาของไปวาง ใช้ปุ่ม **"ดึงกลับไปรอส่งมอบ"** ได้
> แต่**เมลที่ออกไปแล้วเรียกคืนไม่ได้** ระบบจะเตือนก่อนกด

> งานจะค้างที่ **รอส่ง** จนกว่าฝ่ายจัดส่งจะกรอกทะเบียนรถแล้วกดปิดจบ
> เป็นการออกแบบตั้งใจ เพื่อไม่ให้งานถูกปิดโดยที่ไม่มีข้อมูลรถจริง
> และงานที่ **ส่งแล้ว** ย้อนสถานะกลับไม่ได้ เพราะย้อนแล้วของก็ไม่ได้กลับมา

สิทธิ์ทั้งหมดนี้**บังคับที่ฝั่งเซิร์ฟเวอร์** ไม่ใช่แค่ซ่อนปุ่ม — ต่อให้ยิงคำสั่งตรงเข้า API ก็ถูกปฏิเสธ
รวมถึง **อีเมลของ AE** ที่ระบบไปอ่านจากชีต `AEs` เองทุกครั้ง ไม่รับค่าที่ส่งมาจากหน้าเว็บ
จึงสั่งให้ส่งเมลไปที่อื่นไม่ได้ และไม่มีปัญหาอีเมลพิมพ์ผิด

### Dashboard

จัดกลุ่มงานเป็นรายวัน เรียงวันใหม่สุดขึ้นก่อน หัวแต่ละวันบอกจำนวนรวมและแยกตามสถานะ
ในแต่ละวันแบ่ง **รอส่งอยู่บน · ส่งแล้วอยู่ล่าง** กลุ่มที่ไม่มีรายการจะไม่แสดงหัวข้อ

มีปุ่มสลับว่าจะนับงานเข้าวันไหน

| โหมด | ตอบคำถามว่า |
|---|---|
| **ยึดวันบันทึก** (เริ่มต้น) | วันนั้น**ตัด**ไปกี่รายการ |
| **ยึดวันจัดส่ง** | วันนั้น**ส่งออก**กี่รายการ |

> โหมด "ยึดวันจัดส่ง" งานที่ยังไม่ส่งจะไม่มีวันให้จัดกลุ่ม ระบบจึงปักกลุ่ม **"ยังไม่ได้ส่ง"** ไว้บนสุดเสมอ
> เพื่อไม่ให้งานค้างหายไปจากจอเงียบๆ

ช่องค้นหาแยกจากหน้ารายการงาน ค้นได้จาก รหัสงาน · ลูกค้า · รหัสไฟล์ · AE · ปลายทาง · ผู้ติดต่อ · ทะเบียนรถ
วันที่ไม่เหลือรายการตรงเงื่อนไขจะหายไปทั้งกลุ่ม

## ดึงข้อมูลจากระบบ Presales ด้วย request_id

ตอนช่างตัดกด **+** บันทึกงานใหม่ จะมีกล่องฟ้าอยู่บนสุดของฟอร์ม ใส่ `request_id` แล้วกด **ดึงข้อมูล**
ระบบจะไปอ่านฐานข้อมูล Presales มาเติมให้ 3 ช่อง

| ช่องในฟอร์ม | ค่าที่ได้ |
|---|---|
| ลูกค้า | `c_customer_name` |
| รหัสสินค้า | `pi_product_code` + ` \| ` + `pi_saletext1` |
| AE | `created_by` และอีเมล `created_by@scg.com` |

ช่องที่เหลือ (RSC/Tele · DieCut · Accessory · ลอน · จำนวน · กำหนดส่ง · ปลายทาง) กรอกเองเหมือนเดิม

**เป็นทางลัด ไม่ใช่ทางบังคับ** — ข้ามกล่องนี้แล้วกรอกเองทั้งหมดได้ตลอด และถ้าฐานข้อมูลล่ม
จะขึ้นข้อความแดงเฉพาะในกล่องนี้ **ฟอร์มส่วนอื่นและการบันทึกงานยังทำงานปกติ**

AE ที่ยังไม่มีในชีต `AEs` ระบบจะเพิ่มให้อัตโนมัติ (และเปิดใช้งานกลับให้ถ้าเคยถูกปิดไว้) พร้อมบันทึกในชีต `Log`

### ตั้งค่าการเชื่อมต่อ

**รหัสเชื่อมต่อไม่ได้อยู่ในโค้ดและจะไม่มีวันอยู่** เพราะไฟล์ทุกไฟล์ในโฟลเดอร์นี้ถูก push ขึ้น repo สาธารณะ
ใส่เองที่ Apps Script → ⚙️ **Project Settings** → **Script Properties** ให้ครบ 5 ตัว

| Property | ใส่อะไร |
|---|---|
| `DB_SERVER` | โฮสต์ที่ลงท้าย `.database.windows.net` |
| `DB_PORT` | `1433` |
| `DB_NAME` | ชื่อฐานข้อมูล |
| `DB_USER` | ชื่อผู้ใช้ |
| `DB_PASSWORD` | รหัสผ่าน |

> ⚠️ **ห้ามเอาค่าเหล่านี้ไปวางในไฟล์ใดๆ ของโปรเจกต์** ไม่ว่าจะ `Code.gs` `config.js` หรือ README
> บอตสแกนหารหัสใน GitHub ตลอดเวลา และ git เก็บประวัติไว้ — ลบทีหลังก็ยังค้างในประวัติ

### ⚠️ ไฟร์วอลล์ Azure ต้องเปิดให้ IP ของ Google ก่อน

Apps Script ยิงออกจากศูนย์ข้อมูล Google ไม่ใช่จากเครื่องในออฟฟิศ **Azure SQL จึงบล็อกไว้ตั้งแต่แรก**
ต้องเพิ่ม firewall rule ที่ Azure SQL → **Networking** → **Firewall rules** ให้ครบ 11 ช่วง

```
64.18.0.0/20      64.233.160.0/19   66.102.0.0/20     66.249.80.0/20
72.14.192.0/18    74.125.0.0/16     173.194.0.0/16    207.126.144.0/20
209.85.128.0/17   216.58.192.0/19   216.239.32.0/19
```

Azure รับเป็นคู่ start–end ไม่รับ CIDR จึงต้องแปลงก่อน · ขั้นนี้ต้องมีสิทธิ์เข้า Azure Portal

> **บอก IT ตรงๆ ว่านี่คือการเปิดกว้างระดับช่วง IP ของ Google ทั้งหมด** ไม่ใช่ IP เดียว
> ใครก็ตามที่รัน Apps Script ได้จะยิงถึงเซิร์ฟเวอร์นี้ในระดับเครือข่าย (ยังต้องมีรหัสผ่านถึงจะเข้าได้)

### ตรวจว่าต่อติดไหม — ทำก่อนเป็นอันดับแรก

Apps Script → เลือก **`adminTestDb`** → **Run** → ดู **Execution log**
ฟังก์ชันนี้ไม่แก้ข้อมูลอะไร รันซ้ำได้ตลอด และจะบอกว่าติดตรงไหน

| ผลที่ได้ | แปลว่า |
|---|---|
| ✓ ต่อสำเร็จ + ดึงข้อมูลได้ | พร้อมใช้งาน |
| ✗ ขาด `DB_...` | ยังใส่ Script Properties ไม่ครบ |
| ✗ timeout / connection refused | ไฟร์วอลล์ Azure ยังไม่เปิดให้ IP Google |
| ✗ login failed | ชื่อผู้ใช้หรือรหัสผ่านผิด |
| ✗ SSL / TLS | **ไดรเวอร์ของ Apps Script เจรจา TLS กับ Azure ไม่ผ่าน — แก้จากโค้ดไม่ได้ ต้องเปลี่ยนวิธี** |

### ความปลอดภัย

- อ่านอย่างเดียว (`SELECT`) ไม่เขียนกลับเข้าฐานข้อมูล
- เฉพาะ **ช่างตัด** เท่านั้นที่กดดึงได้ · ฝ่ายจัดส่งและ viewer ยิงคำสั่งตรงก็ถูกปฏิเสธ
- `request_id` ถูกกรองให้เป็นจำนวนเต็มบวกก่อนแตะฐานข้อมูล และ SQL ใช้ `?` ผูกค่า **ไม่ต่อสตริง**
- ทุกครั้งที่ดึงมีบันทึกในชีต `Log` ว่าใครดึง request ไหน

## ขั้นตอนติดตั้ง

### ส่วนที่ 1 — ฐานข้อมูลและ API (Google)

> ชื่อเมนูด้านล่างอ้างอิงจาก Apps Script **ภาษาอังกฤษ** (ถ้าของคุณเป็นภาษาไทยจะอยู่ตำแหน่งเดียวกัน)

1. เปิด [sheets.new](https://sheets.new) สร้าง Google Sheet ใหม่ ตั้งชื่อว่า `งานตัดกล่องตัวอย่าง`
2. เมนู **Extensions → Apps Script**
3. ลบโค้ดเดิมทั้งหมดในไฟล์ `Code.gs` แล้วคัดลอกเนื้อหาจากไฟล์ `Code.gs` ในโฟลเดอร์นี้ไปวางแทน
4. กด **Save** (ไอคอน 💾 หรือ `Cmd+S`)
5. เลือกฟังก์ชัน `setup` จากดรอปดาวน์ด้านบน แล้วกด **Run**
   - ครั้งแรกจะขึ้นให้อนุญาตสิทธิ์ → **Review permissions** → เลือกบัญชี → **Advanced** → **Go to ... (unsafe)** → **Allow**
   - ขั้นตอนนี้ปกติ เพราะเป็นสคริปต์ที่คุณเขียนเอง Google เลยยังไม่ได้รับรอง
   - **สิทธิ์ที่ขอจะรวมการส่งอีเมลด้วย** เพราะระบบต้องส่งแจ้งเตือน — ต้องกด Allow ให้ครบ
6. เปิดแท็บ **Execution log** ด้านล่าง → **จดรหัสผ่านเริ่มต้นของทั้ง 4 บัญชีเก็บไว้** (แสดงครั้งเดียว)
   และอ่านหัวข้อ "สิ่งที่ต้องทำต่อ" ที่ระบบพิมพ์ไว้ให้
7. **กรอกรายชื่อ AE ให้ครบ** ← ถ้าข้ามขั้นนี้ ช่างตัดจะบันทึกงานไม่ได้เลย

   ทำได้ 2 ทาง เลือกทางไหนก็ได้ ผลเหมือนกัน

   **ทางที่ง่ายกว่า** — ทำทีหลังบนหน้าเว็บ (หลังติดตั้งเสร็จครบทุกขั้น)
   login เป็นช่างตัด → เมนู **ตั้งค่า** → **+ เพิ่ม AE ใหม่**

   **หรือพิมพ์ลงชีตตรงๆ** — เปิดแท็บ `AEs` แล้วกรอก

   | `name` | `email` | `active` |
   |---|---|---|
   | ศิริกร | sirikorn@scg.com | yes |
   | พรรณเปรี่ยว | pann@scg.com | yes |

   ใส่ชื่อให้ตรงกับที่ช่างตัดเรียกกันจริง เพราะชื่อนี้คือตัวเลือกในดรอปดาวน์

8. กด **Deploy → New deployment**
   - Select type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** ← ต้องเลือกอันนี้ ไม่งั้นหน้าเว็บเรียก API ไม่ได้
9. คัดลอก **Web app URL** ที่ได้ (ลงท้ายด้วย `/exec`)

> **"Anyone" ปลอดภัยไหม?** ปลอดภัยครับ เพราะทุกคำสั่งที่ดึงหรือแก้ข้อมูลต้องแนบ token
> ที่ได้จากการ login เท่านั้น คนที่เปิด URL เฉยๆ จะเห็นแค่ข้อความว่า API พร้อมใช้งาน

### ส่วนที่ 2 — หน้าเว็บ

10. เปิดไฟล์ `config.js` แล้วเอา URL จากข้อ 9 ไปวางแทนค่า `API_URL` เดิม
11. ทดสอบก่อนขึ้นจริง — เปิด Terminal ที่โฟลเดอร์นี้แล้วรัน:

    ```bash
    python3 -m http.server 8000
    ```

    จากนั้นเปิด http://localhost:8000 แล้วลอง login

### ส่วนที่ 3 — ขึ้นเว็บฟรีด้วย GitHub Pages

12. สมัคร [github.com](https://github.com) แล้วสร้าง repository ใหม่ ตั้งเป็น **Public**
13. กด **Add file → Upload files** แล้วลาก **8 ไฟล์นี้** ลงไป จากนั้นกด **Commit changes**

    ```
    index.html   style.css   app.js   config.js
    manifest.json   icon-192.png   icon-512.png   apple-touch-icon.png
    ```

    **ไม่ต้องอัพ `Code.gs`** (อยู่บน Google แล้ว) และไม่ต้องอัพ `README.md`

14. ไปที่ **Settings → Pages → Source: Deploy from a branch → main / (root)** แล้วกด **Save**
15. รอประมาณ 1 นาที จะได้ URL หน้าตา `https://ชื่อผู้ใช้.github.io/ชื่อ-repo/`

เอา URL นี้ส่งให้ทีม 4 คน ใช้ได้ทั้งบนคอมและมือถือ

**บนมือถือแนะนำให้ติดตั้งเป็นแอป** — iPhone: เปิดใน Safari → ปุ่มแชร์ → *เพิ่มไปยังหน้าจอโฮม* /
Android: เปิดใน Chrome → เมนู ⋮ → *ติดตั้งแอป* จะได้ไอคอนกล่องสีน้ำเงินและเปิดเต็มจอไม่มีแถบ URL

### เครื่องมือสำหรับผู้ดูแล

ใน Apps Script มี 5 ฟังก์ชันให้ใช้ — แก้ค่าตัวแปรด้านบนของฟังก์ชัน กด **Save** แล้วเลือกชื่อฟังก์ชันจากดรอปดาวน์ → **Run**

| ฟังก์ชัน | ใช้ทำอะไร |
|---|---|
| `adminTestDb()` | **ตรวจว่าต่อฐานข้อมูล Presales ติดไหม** — บอกว่าติดไฟร์วอลล์ รหัสผิด หรือ TLS แล้วลองดึง request ตัวอย่างให้ดู (ไม่แก้ข้อมูลอะไร) |
| `adminCheckMailSetup()` | **ตรวจว่าอีเมลพร้อมใช้ไหม** — โชว์ผู้รับแจ้งเตือน · สำเนา CC และสถานะสวิตช์ · โควตาที่เหลือและที่ใช้ต่องาน · รหัสยืนยันตั้งหรือยัง · AE ที่ยังไม่มีอีเมล (ไม่แก้ข้อมูลอะไร รันได้ทุกเมื่อ) |
| `adminResetPassword()` | ตั้งรหัสผ่านใหม่ให้คนที่ลืมรหัส |
| `adminAddUser()` | เพิ่มผู้ใช้ใหม่ |
| `adminClearJobs()` | **ล้างข้อมูลงานทั้งหมด** เริ่มนับรหัสงานใหม่ที่ 001 (ไม่แตะบัญชีผู้ใช้และรายชื่อ AE) |

> ฟังก์ชันพวกนี้รันจากหน้า Editor โดยตรง จึงใช้ **โค้ดล่าสุดที่ Save** ทันที — **ไม่ต้อง Deploy ใหม่**
> (ต่างจาก `/exec` ที่ยึดตาม version ที่ deploy ไว้)

ถ้าจะระงับผู้ใช้ชั่วคราว เปิดชีต `Users` แล้วแก้คอลัมน์ `active` จาก `yes` เป็น `no`
(ส่วน **AE** จัดการจากหน้าเว็บได้เลย ดูหัวข้อถัดไป)

## จัดการอีเมลจากหน้าเว็บ

login เป็น **ช่างตัด** แล้วเข้าเมนู **ตั้งค่า** — ทุกอย่างในหัวข้อนี้ทำได้โดยไม่ต้องแตะ Apps Script หรือ Google Sheet
ทุกค่าเก็บใน Script Properties มีผลทันที **ไม่ต้อง Deploy ใหม่**

### อีเมลแจ้งเตือนงานรอส่ง

ช่องบนสุด ใส่แล้วกด **บันทึกอีเมล** · หลายคนคั่นด้วยจุลภาค — `nawinsan@scg.com, somchai@scg.com`

### สำเนา CC

แนบสำเนาไปกับเมลที่ระบบส่งออก · หลายคนคั่นด้วยจุลภาค · **เว้นช่องว่าง = ไม่ CC เลย**

ด้านล่างมีสวิตช์แยก 2 ตัว เปิด/ปิดอิสระจากกัน ใช้ที่อยู่ CC ชุดเดียวกัน

| สวิตช์ | ติดไปกับเมล | ส่งถึง |
|---|---|---|
| CC เมลแจ้ง **"รอส่ง"** | ตอนช่างตัดบันทึกงาน | ฝ่ายจัดส่ง |
| CC เมลแจ้ง **"ส่งแล้ว"** | ตอนกดจัดส่งเสร็จ | AE ของงานนั้น |

**ปิดสวิตช์แล้วที่อยู่ยังเก็บไว้** กดเปิดกลับได้ทันทีไม่ต้องพิมพ์ใหม่

> **⚠️ CC ผู้รับทุกคนมองเห็น** — ต่างจาก BCC ตรงที่ทุกคนในเมลเห็นว่ามีใครอยู่ในสำเนา
> ถ้าเปิดสวิตช์ "ส่งแล้ว" ตัว **AE จะเห็นอีเมลใน CC ด้วย**
> ไม่อยากให้ AE เห็น → ปิดเฉพาะสวิตช์นั้น ยังได้สำเนาของเมลฝั่งจัดส่งครบเหมือนเดิม

> **⚠️ CC กินโควตาเพิ่ม** — Google นับ *ผู้รับ* ไม่ใช่จำนวนฉบับ ดูตารางในหัวข้อ [ข้อจำกัดอื่น](#ข้อจำกัดอื่น)

### โควตาส่งเมล

กดปุ่ม **ตรวจโควตา** เพื่อดูว่าวันนี้ส่งได้อีกกี่ฉบับ อ่านค่าสดจาก Google ทุกครั้งที่กด
สีของตัวเลขบอกสถานะ — เขียว = สบาย · เหลือง = เริ่มน้อย · แดง = ใกล้หมดหรืออ่านค่าไม่ได้

### รายชื่อ AE

ตารางด้านล่าง แก้ชื่อ/อีเมลแล้วกด **บันทึก** ทีละแถว · กด **+ เพิ่ม AE ใหม่** เพื่อเพิ่มคน
AE ที่เพิ่มจะไปโผล่ในดรอปดาวน์ตอนบันทึกงานทันที ไม่ต้อง login ใหม่

**ไม่มีปุ่มลบโดยตั้งใจ** — งานเก่าเก็บชื่อ AE ไว้เป็นข้อมูลในแถวงาน ถ้าลบทิ้งจะกลายเป็นชื่อลอยที่สาวกลับไม่ได้
ให้ติ๊ก **ใช้งาน** ออกแทน ชื่อจะหายจากดรอปดาวน์ตอนบันทึกงานใหม่ แต่งานเก่ายังเปิดดูได้ครบและยังเห็นชื่อ

> **การแก้ชื่อหรืออีเมล ไม่ย้อนไปแก้งานที่บันทึกไปแล้ว** — ตอนบันทึกงานระบบคัดลอกอีเมล AE เก็บไว้ในแถวงานเลย
> งานเก่าจึงยังส่งเมลไปที่อยู่เดิม ถ้าต้องการให้ใช้อีเมลใหม่ ต้องเปิดงานนั้นแล้วเลือก AE ใหม่อีกครั้ง

### ⚠️ ใครแก้ได้บ้าง

**ใครที่รู้รหัสผ่าน `cutter` เปลี่ยนปลายทางอีเมลได้ทั้งหมด** ทั้งอีเมลแจ้งจัดส่งและอีเมลของ AE ทุกคน
นี่คือสิ่งที่แลกมากับความสะดวกที่ไม่ต้องเข้าหลังบ้าน

- ทุกการเปลี่ยนถูกบันทึกในชีต `Log` พร้อม **ค่าเก่า → ค่าใหม่** และชื่อคนที่เปลี่ยน
- **ตั้งรหัส `cutter` ให้แข็งแรงและอย่าใช้ร่วมกันหลายคน**
- ถ้าต้องการแยกความรับผิดชอบจริงจัง ค่อยเพิ่มบทบาท `admin` แยกต่างหากทีหลังได้

### ล้างประวัติทั้งหมด

อยู่ท้ายหน้าตั้งค่าในกรอบสีแดง — ลบ **งานทุกรายการ** และ **บันทึก Log ทั้งหมด**
รหัสงานเริ่มนับใหม่ที่ 001 · **บัญชีผู้ใช้และรายชื่อ AE ไม่ถูกแตะต้อง**

ต้องผ่าน **2 ด่าน** ถึงจะลบได้ — กรอก **รหัสยืนยัน** ให้ถูก และกดยืนยันในกล่องที่เด้งขึ้นมา
ซึ่งจะบอกจำนวนงานที่กำลังจะหายจริงให้เห็นก่อนตัดสินใจ

**รหัสยืนยันเก็บที่ Script Properties → `ADMIN_CODE`** (ค่าเริ่มต้น `ADMINTCRB`)
เปลี่ยนได้ที่ Apps Script → ⚙️ **Project Settings** → **Script Properties** → **Edit**

> **ทำไมไม่ฝังรหัสในโค้ด** — ไฟล์ `Code.gs` ถูก push ขึ้น GitHub ที่เป็น **Public**
> ถ้าฝังไว้ในโค้ด ใครเปิดหน้า repo ก็อ่านรหัสได้ทันที เก็บใน Script Properties จึงเป็นที่เดียวที่ไม่รั่ว
> ด้วยเหตุผลเดียวกัน โค้ด**ไม่มีค่า fallback** ถ้ายังไม่ได้รัน `setup()` ปุ่มจะแจ้งให้ไปรันก่อน ไม่ใช่ปล่อยให้ลบได้

**ทางสำรองเมื่อเข้าหน้าเว็บไม่ได้** — เปิด Apps Script → `adminClearJobs()` → เปลี่ยน `CONFIRM`
เป็น `true` → **Save** → **Run** → ดูผลใน Execution log → เปลี่ยนกลับเป็น `false`

**หรือลบมือในชีต** — เปิดแท็บ `Jobs` → คลิกหัวแถวที่ 2 → `Shift+คลิก` แถวสุดท้าย → คลิกขวา → **Delete rows**
**ห้ามลบแถวที่ 1** เพราะเป็นหัวตารางที่ระบบใช้อ้างอิงชื่อคอลัมน์

> ⚠️ **ลบแล้วกู้จากในระบบไม่ได้** ถ้าลบพลาด ให้กู้จาก **File → Version history → See version history**
> ของ Google Sheet ซึ่งเก็บย้อนหลังให้อัตโนมัติ
> ถ้าอยากเก็บข้อมูลเดิมไว้ก่อน ใช้ **File → Make a copy** สำรองไว้สักชุด

## โครงสร้างข้อมูล

Sheet จะมี 4 แท็บ

- **Jobs** — ข้อมูลงานทั้งหมด แก้ตรงในชีตได้เลยถ้าจำเป็น (หน้าเว็บจะเห็นทันทีเมื่อรีเฟรช)
- **Users** — บัญชีผู้ใช้ (รหัสผ่านเก็บเป็นค่าแฮช อ่านย้อนกลับไม่ได้)
- **AEs** — รายชื่อ AE กับอีเมล ใช้เป็นตัวเลือกในดรอปดาวน์และปลายทางเมลแจ้งตอนส่งเสร็จ
- **Log** — บันทึกว่าใครทำอะไรเมื่อไหร่ รวมถึงกรณีส่งเมลไม่สำเร็จ

### คอลัมน์ในชีต `Jobs`

| กลุ่ม | คอลัมน์ | ใครกรอก |
|---|---|---|
| ระบุงาน | `id` `customer` `fileCode` | ช่างตัด (`id` ระบบสร้างให้) · `fileCode` แสดงบนหน้าเว็บว่า **"รหัสสินค้า"** |
| รายละเอียดกล่อง | `rscTele` `dieCut` `accessory` `flute` `qty` | ช่างตัด |
| ผู้สั่งงาน | `aeName` `aeEmail` | ช่างตัดเลือกชื่อ · **อีเมลระบบเติมจากชีต `AEs`** |
| กำหนดและปลายทาง | `dueDate` `destination` | ช่างตัด (จัดส่งแก้ `destination` ได้) |
| สถานะ | `status` `note` | ระบบ / ทั้งคู่แก้ `note` ได้ |
| ข้อมูลขนส่ง | `contactName` `contactPhone` `vehicle` | **ฝ่ายจัดส่งเท่านั้น** |
| ร่องรอย | `createdBy` `createdAt` `shipBy` `shipAt` `updatedAt` | ระบบเติมอัตโนมัติ |

> ไม่มีคอลัมน์ `cutBy` / `cutAt` เพราะคนที่บันทึกงานคือคนที่ตัด — ดูจาก `createdBy` / `createdAt` ได้เลย

### รหัสงานสร้างยังไง

`SB-2608-001` = `SB` (Sample Box) + `26` (ปี ค.ศ. 2026) + `08` (เดือน) + `001` (ลำดับ)

ตอนบันทึกงานใหม่ระบบจะหารหัสที่ขึ้นต้นด้วย `SB-2608-` ที่มีเลขสูงสุดแล้ว +1
**ลำดับรีเซ็ตเป็น 001 ใหม่ทุกต้นเดือน** และมีการล็อกกันรหัสชนกรณีสองคนกดบันทึกพร้อมกัน

## เวลาแก้โค้ดภายหลัง

| แก้ไฟล์ | ต้องทำอะไรต่อ |
|---|---|
| `index.html` `style.css` `app.js` `config.js` | push ขึ้น GitHub — มีผลใน ~1 นาที |
| `Code.gs` | **ต้อง Deploy ใหม่** ที่ Apps Script (ดูด้านล่าง) |

### วิธี Deploy Apps Script ใหม่

Apps Script แยก "โค้ดที่ Save ไว้" กับ "โค้ดที่เผยแพร่อยู่" ออกจากกัน

| URL | รันโค้ดตัวไหน |
|---|---|
| `/exec` (ตัวที่ `config.js` เรียก) | โค้ดของ **version ที่ deploy ไว้** — ไม่ขยับตามการกด Save |
| `/dev` (Test deployment) | โค้ดล่าสุดที่ Save เสมอ |

กด Save อย่างเดียวจึงไม่พอ ต้องสร้าง version ใหม่ให้ `/exec` ชี้ไปหา

1. **Extensions → Apps Script** → วางโค้ดใหม่ทับ
2. กด **Save** ← ต้องทำก่อน เพราะ version ใหม่จับภาพจากโค้ดที่ Save แล้วเท่านั้น
3. **Deploy → Manage deployments**
4. เลือก deployment ที่มีอยู่ทางซ้าย → กดไอคอน **ดินสอ ✏️ (Edit)** มุมขวาบน
5. ช่อง **Version** → เลือก **New version**
6. ใส่ Description สั้นๆ แล้วกด **Deploy** → **Done**

> ⚠️ **อย่ากด "New deployment"** — อันนั้นสร้าง URL ใหม่ทั้งอัน แล้วต้องกลับมาแก้ `config.js` ใหม่หมด
> ส่วน **Manage deployments → Edit → New version** จะใช้ URL เดิมต่อ

> ⚠️ **ถ้าโค้ดใหม่เพิ่มการใช้บริการที่ยังไม่เคยขอสิทธิ์** (เช่นตอนเพิ่มการส่งอีเมลด้วย `MailApp`)
> ต้องรันฟังก์ชันอะไรก็ได้จากหน้า Editor หนึ่งครั้งเพื่อกด **Allow** ก่อน แล้วค่อย Deploy
> ไม่งั้น `/exec` จะทำงานได้แต่ส่วนที่ต้องใช้สิทธิ์ใหม่จะล้มเงียบๆ — ใช้ `adminCheckMailSetup()` ตรวจได้

**ตรวจว่า deploy ขึ้นจริงไหม** — รันใน Terminal (แทนรหัสผ่านจริง และรหัสงานที่สถานะเป็น "รอส่ง")

```bash
URL=$(grep API_URL config.js | grep -o "https://script[^']*")
T=$(curl -sL "$URL" --data-raw '{"action":"login","username":"cutter","password":"รหัสของช่างตัด"}' \
    | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")
curl -sL "$URL" --data-raw "{\"action\":\"setStatus\",\"token\":\"$T\",\"id\":\"SB-2608-001\",\"status\":\"ส่งแล้ว\"}"
```

ได้ `{"ok":false,"error":"คุณไม่มีสิทธิ์ทำรายการนี้"}` = สำเร็จ (ช่างตัดกดส่งแล้วไม่ได้)
ถ้าได้ `{"ok":true,...}` แปลว่ายังเป็นโค้ดเก่า ให้ทำข้อ 2-6 ใหม่

> ตัว `grep` ต้องเจาะจง `https://script` เพราะในคอมเมนต์ของ `config.js` มี URL ตัวอย่างอยู่ด้วย
> ถ้าใช้ `https://[^']*` เฉยๆ จะได้มาสองบรรทัดแล้ว `curl` พัง

เมลจากภายนอกที่ส่งเข้าโดเมนองค์กรมีโอกาสถูกจัดเป็นสแปมหรือถูกเมลเซิร์ฟเวอร์ตีกลับ

ควรทำ 2 อย่างตั้งแต่วันแรก
1. ให้ผู้รับทุกคน **เช็คโฟลเดอร์ Junk / Spam** ในช่วงสัปดาห์แรก เจอแล้วกด *Not junk*
2. ถ้าเมลหายบ่อย ขอให้ IT เพิ่มอีเมลผู้ส่งเป็น **safe sender** ในระบบเมลองค์กร

**นี่เป็นข้อจำกัดที่ควบคุมจากฝั่งระบบเราไม่ได้** ถ้าต้องการความแน่นอนกว่านี้
ต้องส่งผ่านเมลเซิร์ฟเวอร์ของ SCG เอง ซึ่งเกินขอบเขตของเครื่องมือฟรีชุดนี้

### ⚠️ โควตา — CC กินเพิ่มเท่าตัว

Gmail ทั่วไปจำกัด **100 ผู้รับ/วัน** และ Google นับ **ผู้รับ** ไม่ใช่จำนวนฉบับ
งานหนึ่งรายการส่ง 2 เมลอยู่แล้ว (แจ้งรอส่ง + แจ้ง AE) เปิด CC เพิ่มก็คูณขึ้นไปอีก

| ตั้งค่า CC | ผู้รับต่องาน | ที่ 17 งาน/วัน |
|---|---|---|
| ปิดทั้งสองสวิตช์ | 2 | 34 |
| เปิดสวิตช์เดียว | 3 | 51 |
| เปิดทั้งสองสวิตช์ | 4 | **68** |
| เปิดทั้งสอง + CC 2 คน | 6 | **102** ❌ ชนเพดาน |

ใส่ผู้รับหลายคนใน `NOTIFY_EMAIL` ก็นับคูณตามจำนวนคนเช่นกัน

**ชนเพดานแล้วเมลหยุดส่งเงียบๆ** งานยังถูกบันทึกปกติแต่ไม่มีใครได้เมล
จะเห็นบรรทัด *"ส่งเมลไม่สำเร็จ"* ในชีต `Log` · กด **ตรวจโควตา** ในหน้าตั้งค่าดูได้ทุกเมื่อ

### ข้อจำกัดอื่น

- **อีเมลไม่ใช่ระบบยืนยัน** — ถ้าส่งเมลล้ม งานยังถูกบันทึกและเห็นบนหน้าเว็บปกติ
  **ให้ยึดหน้าเว็บเป็นความจริง** อีเมลเป็นแค่ตัวเตือน · กรณีส่งไม่สำเร็จจะมีบรรทัดในชีต `Log`
- AE ที่ไม่มีอีเมลในชีต `AEs` จะบันทึกงานให้ไม่ได้ ระบบจะแจ้งว่า *"ยังไม่มีอีเมลในชีต AEs"*

## ข้อควรทราบ

- ระบบจะจำการ login ไว้ 12 ชั่วโมง แล้วให้ล็อกอินใหม่
- **บันทึกงานแล้วเป็น "รอส่ง" ทันที** ไม่มีขั้นตรวจก่อน ถ้ากรอกผิดให้กด *ยกเลิกงาน* แล้วบันทึกใหม่
- Google Sheets รองรับงานหลักพันรายการสบายๆ ถ้าเกินหลักหมื่นแล้วเริ่มช้าค่อยพิจารณาย้ายฐานข้อมูล
- ข้อมูลลูกค้าปลอดภัยระดับ "กันคนนอกทั่วไป" เหมาะกับการใช้งานภายในองค์กร
  ถ้าอนาคตต้องการมาตรฐานความปลอดภัยสูงกว่านี้ ค่อยย้ายไป Supabase ที่มีระบบ auth เต็มรูปแบบ
- คนที่เข้าถึง Google Sheet ได้จะเห็นข้อมูลลูกค้าทั้งหมด — อย่าแชร์ Sheet ให้ใครนอกทีม
